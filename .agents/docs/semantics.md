# Limina semantic facts

[English](./semantics.md) | [简体中文](./zh/semantics.md)

This page explains how dependency facts are produced and the limits of their capabilities. Entity and relation definitions belong to the [system model](./system-model.md); properties that must not change accidentally belong to [I02–I07](./invariants.md). This page describes the current adapters, without claiming complete equivalence to every version of the upstream checkers.

The shared declaration projection visits each file inventory once per semantic context. Links retain every predecessor request and one entry reachability witness, rather than materializing every root-to-file path.

## Independent Native Evidence contract

**Current implementation:** [Native Evidence v5](../../packages/limina/src/domain/analysis/native-evidence.ts) feeds the Native provider and schema 12. The domain contract carries no Program, AST, Host or execution authority and adds no user API. It retains requests, raw resolutions, Coverage, stops, project relations, compilation obligations, completeness and execution failures. [Publication](../../packages/limina/src/domain/analysis/native-evidence-freeze.ts) copies and freezes JSON data, rejecting compiler handles, mutable collections, accessors and cycles. Production acceptance and version compatibility remain separate gates; wiring the implementation does not establish that those gates passed.

**Coverage proof:** [the index contract](../../packages/limina/src/domain/analysis/native-coverage.ts) requires a universe established by activated entry selection and solution traversal before successful parsing is known. Extends inputs, generated configs and declaration artifacts do not become owners. Closed discovery, current configuration enumeration and verified file identities are required to prove zero or one membership. Unbounded parse failures keep the relevant universe incomplete; only an evidenced exclusion of the target identity limits their impact. Both lexical and canonical membership require current verified identities for the target and member; stale or unavailable identities cannot count as confirmed members. Lexical membership does not skip canonical alias checks. Two confirmed different members prove ambiguity even in a partial index; otherwise incomplete evidence is unavailable. File identity evidence establishes equivalence, not additional scope.

[Coverage member views](../../packages/limina/src/domain/analysis/native-coverage-members.ts) index only privately published immutable enumerations. They preserve the first current canonical match in enumeration order, even when a later member has the exact lexical spelling, and retain stale verified lexical conflicts separately from positive membership. Unpublished mutable inputs remain freshly examined. These views accelerate the existing proof and do not choose the universe, establish physical identity or grant restoration authority. [Coverage contract tests](../../packages/limina/src/__tests__/native-evidence-contract.spec.ts) exercise both published and mutable representations, alias ordering and shallow-frozen caller mutation. Implementation consumers use a separate compiler-key member view over the same enumeration, retaining every lexical spelling and applying the compiler Host case policy. They never use the physical first-match fallback to choose a compilation unit.

**Compilation proof:** [obligations](../../packages/limina/src/domain/analysis/native-obligation.ts) keep existence, reference structure and declaration availability independent. Proven existence plus unsatisfied structure is `required`; proven existence plus satisfied structure is `already-satisfied`; proven absence is `not-required`; other combinations are `unknown`. Context, raw references and endpoint mappings must match. Missing or stale output does not erase satisfied structure. File existence alone does not establish available output. A resolved target, owner, load attempt or TypeEvidence cannot independently supply the existence proof.

**Request-local proofs:** `absent` negates only the current request's cross-unit obligation. Compiler-inventoried augmentation, effective module `noResolve` (including unavailable resolution), and a proven consumer root supply independent absence. Resolution, Coverage, ownership and other requests survive. `present` additionally requires an eligible input/emit target, qualified source classification and the existing composite/generated-declaration compilation scope. Import diagnostics, JSDoc and per-source options remain distinct from path selection. The shared TS/JS qualification recognizes only supported TS and four JS extensions and keeps `noEmitForJsFiles` separate from Program membership. Module input permission uses effective `allowJs`; an already selected path is not rejected again by that module rule. A redirected JS path with unproved producer emit retains unknown rather than borrowing the consumer's JS suppression rule. `allowNonTsExtensions` does not give arbitrary files JS identity. JSON emit remains unproved. `sourceFileMayBeEmitted` is only a test Oracle on a real target SourceFile, not a request-introduction proof or loading authority. On TypeScript 5.4/5.5, missing per-source callback options remain unavailable rather than borrowing global options.

**Reference observations:** [the compiler adapter](../../packages/limina/src/core/typescript-semantic/reference-redirect.ts) distinguishes completed no association, project membership without `outputDts`, concrete declaration mapping and audited local API unavailability. Pending candidates stop physical fallback until the existing bounded passes converge. Each pass rebinds loading observations to its Program; final compiler inventory targets are observed before publication. [Facts](../../packages/limina/src/core/typescript-semantic/native-program-facts.ts) reuse those observations without calling a getter after freezing. Membership without a declaration path preserves the raw reference and may probe the original path; it never invents a redirect. TypeScript 5.4 has no JS reference exception, 5.5–5.8 use the compiler's qualified project membership predicate, and 5.9/6.0 use the actual source-map result. Their declaration-input associations need not be identical: 5.9.0–5.9.2 omit declaration inputs (5.9.3 restores the association), so an empty lookup cannot prove missing reference structure for those targets. A resolution callback's redirect is the importer's resolution context, not target reference-structure proof.

**Unknown versus failure:** An audited missing Reference Map API is a local unknown/selection stop. It creates no `NativeEvidenceFailure`. A getter that exists but throws records a real failure through the existing snapshot contract: `run: unavailable`, incomplete traversal and no complete cache reuse. Independently established absence is retained in either case. An unavailable resolution can coexist with `not-required`, completed observation execution and undetermined compilation relations; absence never deletes its resolution gap. [Structure projection](../../packages/limina/src/core/typescript-semantic/native-obligation-projection.ts) can prove `unsatisfied` from a proven endpoint and empty effective references or a completed map with no association. Membership alone remains `unknown`; a concrete current consumption mapping can prove `satisfied`. Artifact readiness cannot reverse these conclusions. A typed candidate reference may discharge necessary unknown risk without rewriting raw evidence; a framework schedule cannot replace a declaration reference.

**Proof restoration:** Audited-rule existence proofs bind their evidence ID to a request ID and current context. Generic compiler-observation proofs retain their independent observation IDs. [Bounded restoration](../../packages/limina/src/core/analysis-cache/bounded-context-validity.ts) additionally checks this Native producer's one-request audited provenance, obligation identity, current request existence and input/context bindings before accepting fact/snapshot copies. Every retained compiler request must have exactly one obligation assessment, including absent and unknown assessments. With no raw references, a claimed target must match unique Coverage derived from that request's resolution; reference-bearing contexts retain the compiler mapping's endpoint priority. Missing assessments or mismatched targets revoke restoration and trigger cold collection. Equal copies and valid storage checksums do not establish these joins. The adapter identity invalidates older proof semantics without changing the DTO/schema or cache completeness definition. The cache's supported warm tuple remains narrower than cold compiler compatibility. [Observation](../../packages/limina/src/__tests__/native-program-observation.spec.ts), [proof](../../packages/limina/src/__tests__/native-evidence-contract.spec.ts), [Admission](../../packages/limina/src/__tests__/analysis-completion.spec.ts) and [real-store corruption](../../packages/limina/src/__tests__/full-analysis-cache.spec.ts) tests own these separate boundaries. External-library qualification remains request-specific. Unmanaged declarations retain consumer-context analysis under the shared responsibility rule; this does not authorize non-root implementation expansion or assume external-library emission behavior.

**Phase qualification:** [context contracts](../../packages/limina/src/domain/analysis/native-context.ts) retain actual TypeScript implementation/version, host, roots/options/raw-reference fingerprints, source and coverage versions, toolchain, epoch and collection identity. Pending Native observations can support baseline analysis and ownership selection; unqualified physical candidates only support selection; separately qualified supplemental assessments can establish compilation obligations. Locking requires a new context and collection, including a TypeScript-to-TypeScript lock. Locked facts must be freshly collected by the selected semantic family. Input, epoch, phase, collection or locked selection-evidence changes revoke current eligibility without changing historical evidence. Ambiguous selection and a second lock are explicit conflicts; the contract has no retry loop or final executable Checker field. These are data/producer contracts, not authentication of arbitrary forged JavaScript objects.

**Physical boundary:** The Bounded Host admits real implementation roots and declaration roots with current membership in the source configuration. Shared declaration roots remain independent inputs of each project. External managed declarations are physically withheld before SourceFile creation; incoming requests and resolutions survive. Generated contexts explicitly carry their source configuration identity. Candidate validation grants selected declarations separate bounded loading authority. Its observations cannot become source-analysis facts or consumer compilation edges. Non-root implementations remain bounded. Unmanaged declarations, including third-party declarations, retain consumer-context requests; managed declarations delegate only after candidate validation. Installed retained declarations require observed installation and lock coverage for persistent restoration. Full Programs remain test Oracles.

Path candidate eligibility uses the compiler’s effective `resolveJsonModule` value, including version-dependent defaults. An omitted option must not turn a selected JSON input into proven absence; unproved JSON emission retains unknown and candidate-impact admission. The Native adapter identity invalidates older selection receipts.

**Path selection before loading:** [Selection receipts](../../packages/limina/src/core/typescript-semantic/native-path-selection.ts) probe the qualified compiler candidate order against real existence and its actual reference map before SourceFile creation. Coverage withholding cannot select a lower-priority `.tsx` or `.d.ts`. [Load grants](../../packages/limina/src/core/typescript-semantic/native-program-loads.ts) require a true root or a selected request from an admitted source, as well as Coverage. An independently introduced alternative keeps its own ancestry. Late grants and reference-map discovery use fresh bounded passes over identical roots/options/references; no fake SourceFile, root expansion or full Program fallback is used. Missing redirect output may permit the compiler’s ordinary fallback; existing withheld output may not. Unproved occurrences remain scoped unavailable. [Path regressions](../../packages/limina/src/__tests__/native-path-selection.spec.ts) compare target, complete SourceFile set, subsequent requests and relationships. Compiler source classification is separately qualified: a lower declaration loaded through an independent external entry may inherit metadata from the blocked path fallback. That source and its loaded non-root descendants retain raw observations, but affected emission obligations remain scoped unavailable; declaration-only absence proofs and independent roots remain usable.

**Compilation admission:** [Typed prerequisites](../../packages/limina/src/core/build-graph/compilation-prerequisite.ts) join original requests to their own resolution targets and verified complete/unique Coverage in the current locked context registered by the producer, rather than comparing a cached origin with itself. Deserialized or unbound candidates have no runtime projection qualification. Evidence qualification is separate from proven obligation existence: the required-only dependency writer retains its contract, while Admission can qualify necessary unknowns. Projection uses the selected source's semantic/framework capability and the producer's shared declaration-versus-source selection rule, not whichever candidate edge happens to exist. Required, already-satisfied and necessary unknown relations use the same identity and relationship-kind checks. Source config, Checker, actual generated config and current projection all participate in reference identity, including originally already-satisfied obligations. A declaration obligation needs a declaration reference; an endpoint-matching framework schedule cannot satisfy it. A matching reference may discharge candidate risk without rewriting an unknown raw obligation. Source-consuming Svelte/Astro capabilities do not imply that a provider Checker process must run. Execution rechecks the selected scope against actual references; its lifetime and failure rules are owned by [execution admission](./lifecycle.md#managed-checker-execution-admission). [Admission tests](../../packages/limina/src/__tests__/analysis-completion.spec.ts) use real required, unknown and already-satisfied Native evidence, exercise current-context and typed-reference substitution, and preserve the raw state.

## From ownership candidates to a locked context

[checker-ownership-resolution](../../packages/limina/src/core/build-graph/checker-ownership-resolution.ts) performs discovery, root evidence collection, dependency fact collection, and requirements convergence before freezing semantic authority; Vue promotion, build coloring, and finalization follow. [semantic-authority](../../packages/limina/src/core/build-graph/checker-semantic-authority.ts) accepts only explicit, config, root-file, and dependency evidence for a semantic lock. Build-closure, fallback, and vue-promotion do not rewrite semantics.

Equality edges come only from qualified declaration dependencies, valid declaration-context choices and implicitRefs. Vue promotion and component coloring share declaration-relation qualification; solution aggregation and framework scheduling do not propagate colors. Explicit ownership applies before freezing; execution coloring cannot rewrite frozen semantic authority.

Pending discovery uses the native dependency context from [pending-facts](../../packages/limina/src/core/build-graph/checker-ownership-pending-facts.ts). Framework inference reads qualified `pending-framework-candidate` provenance; it does not manufacture a missing TypeEvidence observation. During [physical candidate](../../packages/limina/src/core/build-graph/checker-ownership-physical-candidate.ts) bootstrapping, Oxc supplies a physical candidate, but a known framework extension, governed effective membership, a unique config, and a semantic domain are also required to form an ownership requirement. An ordinary TS/resource path does not lock a framework merely because a physical lookup succeeds. Native source requirements support compilation, not framework semantic authority. A physical declaration resolution blocks Oxc bootstrapping independently of type evidence. A specifier that carries a query or fragment, such as `./Widget.svelte?x`, never bootstraps a physical candidate either: without a checker target, Limina has no authority to reinterpret host syntax through Oxc or the filesystem. Vue custom profiles are matched using owner-registered compiler members, without physical ownership fallback.

**Controlled Pending supplements:** [request discovery](../../packages/limina/src/core/import-analysis/supplemental-resolution.ts) uses the original Compiler Inventory occurrence, effective source options, mode, complete specifier and a fresh Oxc resolver. Native physical hits bypass this path. Hit, completed miss, unsupported profile, unavailable observation and execution failure remain distinct; raw Native resolutions and obligations remain unchanged. The resolver does not add roots, loading grants, SourceFiles or recursive source traversal. For a target with an existing Vue profile, the consumer Vue resolver supplies the compiler path before implementation membership is selected. Oxc discovery remains unchanged and cannot substitute its physical path for that compiler path. Locked supplements reacquire the compiler target and verify the selected membership; reference recording and duplicate elimination use that target, not physical equivalence.

[Supplemental assessment](../../packages/limina/src/core/build-graph/pending-supplemental-assessment.ts) obtains actual Vue/Volar resolution and matching consumer/owner Service Script classification, then calls the same module-input and obligation projections as Native. Physical identity and current unique Coverage are required; membership alone cannot prove an input. Pending evaluation does not request a consumer Program. The existing Locked recollection rebinds the occurrence, source version, role and mode to real Compiler Inventory, reads current options and reacquires resolution/capability evidence. Supplements have their own context and audited-rule proof; they cannot qualify through Native fact APIs. Reference inputs reuse provider selection, build coloring, contribution replacement and candidate/execution admission. Unknown qualification blocks affected admission, including a custom owner extension the consumer cannot interpret. Native hits and qualified real Checker contributions take precedence over duplicate supplemental contributions.

The first supplemental obligation adapter covers Vue implementation targets. Other framework physical candidates retain their selection contract. Declaration inputs continue through shared Checker-neutral declaration governance and its actual tsc or Vue candidate adapter; unsupported custom-plugin delegation stays unavailable rather than bypassing capability qualification. No Oxc declaration closure, new Source Config, expanded region or mutually dependent capability proof is introduced. Generated output availability is separate from obligation existence. `noResolve`, augmentation, root identity, effective JS input/emit rules and reference mappings retain their common semantics; ambient TypeEvidence, type-only imports, `skipLibCheck` and `noCheck` are not general obligation-cancellation rules.

A locked [ProjectSemanticContext](../../packages/limina/src/core/project-dependencies/contracts.ts) requires `LockedSemanticAuthority` at the type level. It has a different entry point from pending discovery. Copying authority in a constructor is not complete runtime authentication of an arbitrary forged JavaScript object. Production calls are constrained by the solving flow and type boundary; this must not be described as an unforgeable security capability.

## Native semantic inputs for a project

[The dependency entry](../../packages/limina/src/core/typescript-semantic/index.ts) has one Native discovery authority: [the version-adapted TypeScript observation adapter](../../packages/limina/src/core/typescript-semantic/native-observation-adapter.ts). Requests come from actual compiler inventory, including own ambient modules that bypass resolver callbacks, repeated occurrences, JSX/helper imports, triple-slash references and types/lib. The host preserves raw resolution, options, types, lib and raw references. Ordinary collection calls neither TypeChecker, full semantic diagnostics nor emit. Explicit TypeEvidence requests retain a separate lifecycle.

[Effective roots](../../packages/limina/src/core/typescript-semantic/effective-roots.ts) still come from configuration parsing. A→B.ts→C.ts stops at B in A. For A→b.d.ts→C.ts, policy supplies A→B and B’s independently observed implementation obligation supplies B→C. Neither B’s closure nor an old interpretation under A’s paths is flattened into A’s direct edges.

The existing TypeScript support range remains 5.4–5.9 and 6.0. The narrow adapter uses compiler callback redirect options in 5.4/5.5, the compiler library map and normalizer before 5.8, and paired reference redirect methods before 5.9. Later versions use their exposed Program methods. The actual version and implementation remain part of context identity. [Packed Native smoke](../../smoke/native-compiler.spec.ts) exercises installed peers at each minor floor; future patches and prereleases still require API qualification and are not proven by those samples. Persistent Native DTO reuse retains its existing 6.0.3 capability boundary; other supported versions collect fresh Bounded Programs, without an alternate discovery algorithm.

Unsupported compiler versions or observation APIs produce explicit unavailability/failure, without changing algorithms. JS, virtual configurations and original references do not trigger a Programless fallback. Each cold collection constructs a fresh Bounded Program and then releases compiler handles; this version retains no `oldProgram`. Valid complete DTOs can restore without a Program; invalidated contexts are recollected. Hook counts never establish completeness.

[The obligation adapter](../../packages/limina/src/core/typescript-semantic/native-program-obligations.ts) separates source options from the audited generated-declaration-project rule and retains raw reference/redirect mappings. Resolution, Coverage ownership, loading attempts and type evidence cannot independently create compilation edges. Satisfied reference structure can coexist with missing/stale output; unknown output is not available output. Generated outputs receive independent contexts with actual projected options and references, without replacing source facts.

## Declaration entry governance

[Declaration closure projection](../../packages/limina/src/core/typescript-semantic/native-closure.ts) consumes already collected, physically bounded facts, retaining entries, final occurrences, supporting paths and normal stop reasons. It does not repeat a package-origin admission policy. Relative imports, paths, package imports, public package entries, managed outputs and replacement libraries obey the same Coverage rule; resolution origin explains the result without granting exemptions.

Multiple declaration memberships permit expansion. Implementations require complete uniqueness proof and still stop when non-root. Uncovered input does not automatically create a governance violation. Actual `noResolve` behavior limits loading; successful resolution cannot fill in a missing obligation. `skipLibCheck` grants no permission to delete inputs. Removing the last entry revokes unreachable cycles; independent entries and diamond predecessors retain their provenance. [Declaration regressions](../../packages/limina/src/__tests__/declaration-policy.spec.ts) cover package branches, configuration entries, cycles, alias rebinding and an independent Oracle.

Core visits all trusted qualified entries. Expected Coverage boundaries, confirmed ambiguity, ordinary misses and unknown obligations stop only their branches. Configuration/file/compiler/internal failures carry separate impact scopes, while independent contexts retain evidence. [Analysis outcomes](../../packages/limina/src/core/build-graph/analysis-outcome.ts) distinguish execution, bounded traversal, compilation completeness, Governance and materialization Admission. Governance cannot rewrite raw facts; projection cannot drop denied/unknown relationships and claim completeness. The Core worklist records baseline, selection and locked eligibility/execution separately. Draining all eligible work can complete with unavailable authority; skipping eligible work cannot. Execution failure IDs are distinct from unavailable evidence. Governance denial or a failed output projection changes only the graph transaction, never completed Core work. Admission checks the concrete candidate’s necessary entries and compilation references; unknown evidence outside those prerequisites is not a blanket veto. Completed traversal does not imply determined compilation relations. Candidate prerequisites retain declaration references and framework scheduling separately. An existing qualified candidate relation can discharge the same target prerequisite even while an occurrence obligation remains unknown; absent necessary relations still block admission. Actual collection failures are reported after eligible independent work has drained, without being reclassified as governance violations. Conflicting explicit semantic families make only their affected terminal entries unavailable; same-family checker conflicts remain governance decisions.

Checker ownership retains toolchain and semantic-script failures as execution failures with affected contexts, while preserving independent project evidence; these failures do not become governance violations. Ordinary resolution misses may inform migration reports without failing Core execution. At Coverage boundaries migration keeps relation completeness undetermined and conservatively preserves native references; known edges are not a complete relation set.

## Persistent importer validity

[Bounded context capture](../../packages/limina/src/core/analysis-cache/bounded-context-capture.ts) stores complete compiler inventory, occurrence facts and actual input receipts. Schema 12, Native adapter/domain versions and collection mode jointly reject old Programless success graphs; old caches are neither converted nor deleted. Roots/options/raw references, the configuration universe, current lexical/canonical identity, positive/negative probes, directories, manifest conditions and installation environment qualify restoration. Equal importer text does not prove an old context valid.

[Restoration binding](../../packages/limina/src/core/build-graph/native-cache-binding.ts) joins the graph, validated contexts, raw snapshots and locked ownership facts; cached summaries or owner fields cannot grant themselves qualification. Normal Coverage stops can restore completely. Execution failures, unknown installation evidence, incomplete channels or forged bindings force cold collection. Invalid consumers atomically replace contributions, without joining old success and new failure into a complete graph. Complete Native hits create no Program; cold/changed contexts construct a new Bounded Program and do not promise changed-file-only parsing. See [lifecycle](./lifecycle.md#persistent-native-analysis-cache) and [fresh-process regressions](../../packages/limina/src/__tests__/full-analysis-cache.spec.ts).

[Normalized graph views](../../packages/limina/src/core/build-graph/native-graph-views.ts) reference qualified context Coverage, Native evidence and occurrence facts instead of persisting independent copies. The compiler-produced inventory remains a separate completeness witness and is never regenerated from the facts it must check. Ordered occurrence references preserve multiplicity and diagnostic positions. Physical membership uses lexical/canonical path and file binding identity independently of source content; a body edit invalidates its subscribed context without pretending that every overlapping Coverage membership changed. Declaration targets observed by a Bounded context also retain a separate replayable metadata receipt, including when the frontier stops before SourceFile creation. This preserves producer-output refresh and execution-admission drift checks without changing workspace membership. [Execution handoff tests](../../packages/limina/src/__tests__/execution-input-handoff.spec.ts) cover related and unrelated output changes and concurrent producer/consumer handoff. Context replacement still updates dependencies, facts and contributions together.

[Bidirectional cache checks](../../packages/limina/src/core/analysis-cache/bounded-inventory-validity.ts) require actual Program members to match the source/importer set and join compiler requests with source occurrences to occurrence/fact records one-to-one. Deleted, orphaned or duplicate records cannot obtain completeness through empty sets. Config-level requests do not require source occurrences, and legitimate members without imports remain present. Raw requests and resolutions must also match one-to-one. Store parsing and [context adoption](../../packages/limina/src/core/analysis-cache/context-records.ts) use the same checks, so graph rejection cannot reuse a context with missing facts. A frozen compiler inventory receipt is captured before Program disposal: it binds each raw request to its exact occurrence (UTF-16 range, kind, ordinal and synthetic metadata), the complete SourceFile set, admitted roots and actual loaded-source aliases. Restoration compares consumer projections against that receipt and joins every successful load back to an actual member; matching two truncated projections is insufficient. Redirect targets keep the SourceFile returned by the compiler, without requiring lexical path equality. Missing receipts and old adapter identities require cold collection; recovery never regenerates receipts from cached projections. Only a valid context may survive graph-only rejection. The checks revoke cache reuse only: they do not turn scoped unavailable into execution failure or rewrite completed Core work. Damaged stores follow the existing complete-model cold fallback; direct context restoration preserves independent valid contexts. [Real-store regressions](../../packages/limina/src/__tests__/full-analysis-cache.spec.ts) cover source/occurrence/fact damage inside valid checksum envelopes, recollection, publication and next-process restoration. This does not establish that a normal producer naturally emits such damage.

[Vue analysis records](../../packages/limina/src/core/analysis-cache/vue-records.ts) support physical projects using TypeScript 6.0.3, vue-tsc and language-core 3.2.4, and Volar TypeScript 2.4.27, without custom Vue plugins. Stable identity includes effective options, raw references, source profiles, config closure and toolchain identity, while runtime generation is rebound on restore. Supported preparation facts, mapped resolutions and resource type evidence are validated DTOs queried before acquiring a live Vue context. Query coverage must be complete. Host reads, full manifest content, successful and failed probes, directory/path bindings, generated-script/mapping digests and installation environments form the context receipt. Unobserved directory enumeration and unsupported/opaque results cannot grant completeness. Tool module bytes and bindings are observed afresh per invocation. Vue collections use their existing Vue context for direct-source observations and support inputs, with separate query coverage from resolution and preparation.

The mixed graph requires every contributing native and Vue context to be complete. Its Vue references resolve to current parsed identities; Program, AST, Symbol, callable hosts, plugin objects and artifact authority never enter the DTO. Custom plugins, virtual inputs and Astro/Svelte retain cold fallback. [Vue cache regressions](../../packages/limina/src/__tests__/vue-analysis-cache.spec.ts) cover fresh processes, invalidation, partial records, runtime generation and cache access policy. This is analysis reuse; checker diagnostics and emit still follow checker execution.

## Occurrences, evidence, and graph requirements

The Native flow is actual compiler request → raw resolution → Coverage frontier → independent obligation proof → qualified locked fact → reference projection. No handwritten request list gates Native discovery.

| Request                                        | Native/runtime boundary                                                                                                                                                                                            |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| import / export / import type / dynamic import | Preserve compiler occurrences, modes, repeated locations and actual resolution.                                                                                                                                    |
| CommonJS                                       | Compiler-recognized JS require, including its actual shadowing behavior, is Native. Ordinary TS require/createRequire stays in the separate runtime collector and does not automatically create compilation edges. |
| ambient / augmentation                         | Preserve own ambient fast paths. A compiler-inventoried augmentation proves request-local absence; a resolution hit alone cannot establish its role.                                                               |
| JSDoc / declarations                           | Follow actual TS/JS compiler inventory and each declaration's Coverage, without scanning arbitrary comment strings.                                                                                                |
| path / types / lib / JSX / helper              | Preserve separate channels, configuration provenance and real implicit requests; do not delete types/lib or manufacture roots.                                                                                     |

[The runtime source collector](../../packages/limina/src/core/project-dependencies/runtime-source.ts) retains lexical require, createRequire and require.resolve for source/package governance and graph export. Its request purpose, cache identity and output qualification are separate from Native; `referenceRequirement` is null. Graph Check obtains Native targets from [proved obligations](../../packages/limina/src/core/typescript-semantic/native-fact-qualification.ts), without deriving them again from FileOwnerLookup hits.

Graph Check consumes proved uncovered implementation facts through [a separate workspace Governance consumer](../../packages/limina/src/graph-check/native-coverage-governance.ts). Existing source-package policy can report an unmapped/outside-graph import independently of compilation obligation eligibility. Unavailable Coverage and declaration stops do not qualify for that finding; missing or untyped package entries retain their existing runtime-policy finding. This consumer never creates reference edges. The filesystem detector fixtures retain both policy counterexamples and the denied generated reference, which must remain visible in the graph.

TypeEvidence is a separate on-demand type proof and cannot create or erase compilation obligations; the actual Checker owns pure type diagnostics. Complete specifiers, including query/fragment syntax, retain identity, and Oxc never rewrites Native misses as compiler successes. Framework mappings, capabilities and schedules remain owned by their adapters; runtime-use cannot become a Native reference.

JSDoc location binds an existing occurrence to parsed AST nodes, including every adjacent comment block; the public TypeScript tag-ownership helper omits some compiler requests. The [locator](../../packages/limina/src/core/typescript-semantic/source-file-literals.ts) preserves exact UTF-16 ranges and node identity without discovering requests, synthesizing SourceFiles or resolving by specifier alone. Framework type queries rebind detached candidates to the current Program and require that its inventory contains the same JSDoc literal before querying a Symbol. Missing metadata, unmatched or ambiguous ranges remain scoped unavailable; a located compiler miss remains missing, and independent observations survive. [JSDoc regressions](../../packages/limina/src/__tests__/jsdoc-semantic-location.spec.ts) cover the original node:test annotation, repeated occurrences, @import, ignored documentation, noResolve and physical truncation. Cache adapter identities invalidate prior observations; no roots, compiler options, references or discovery authority change.

Framework support-input expansion locates eligible module occurrences in one parsed-source batch, matching specifier and exact range while rejecting ambiguous nodes. The index exists only for that expansion; mutable ASTs and later contexts are read afresh. The CommonJS collector prepares its lexical scope graph lazily at the first literal call candidate, retaining whole-file shadowing, alias and reassignment checks. This removes repeated AST work without changing admission, resolution or discovery authority. The [import collector](../../packages/limina/src/__tests__/import-analysis.spec.ts) and [occurrence regressions](../../packages/limina/src/__tests__/jsdoc-semantic-location.spec.ts) retain computational bounds alongside semantic counterexamples.

## Locked resolution and framework preparation

Vue compiler-purpose discovery enumerates the existing Vue Program's module requests and input directives, including ordinary TS/JS support files and actual SFC service scripts. [Compiler request records](../../packages/limina/src/core/vue-semantic/compiler-requests.ts) retain occurrence, role and resolution mode; the Program-facing bounded Host observes resolution before masking foreign implementations. Support preparation and manual runtime resolution cannot populate that receipt. Compiler reuse retains observations across bounded passes; a masked miss without an observation remains unknown. Synthetic JSX and importHelpers metadata decorate existing compiler requests and never invent them.

[Vue compilation obligations](../../packages/limina/src/core/vue-semantic/compilation-obligation.ts) distinguish present, absent and unknown independently of TypeEvidence and membership. Effective noResolve, augmentation, consumer roots, input/emit eligibility and real redirects qualify each request. Module input qualification uses the resolver's extension, so a physical `.vue` path cannot hide a JS service script from effective `allowJs` or JS emit rules. A framework positive proof also requires matching service extension and ScriptKind; service existence alone is insufficient. The consumer's root profiles do not describe foreign targets. Mapped SFC requests retain strict source mapping and candidate agreement. Ordinary TS require is runtime syntax only, while compiler-inventoried JS require survives lexical shadowing. Missing proof cannot use a resolution-only fallback. [Graph regressions](../../packages/limina/src/__tests__/generated-graph.spec.ts) cover these contrasts, import-equals, path directives and implicit JSX input; framework Programs and governance boundaries remain distinct.

Actual compiler inventory entries without a source-character mapping retain `compiler-request` provenance and an explicit no-range locator. Type-input receipts reparse the generated inheritance and overrides through the compiler instead of merging old parsed options; version 4 revokes older projections and requires loading-identity evidence.

[Library projection](../../packages/limina/src/core/build-graph/library-projection.ts) preserves TypeScript's library selection when generated configurations move the lookup origin. No declaration content is copied, no library becomes an ordinary configured type, and `libReplacement` remains inherited.

Library receipts bind the actual compiler, source/generated config and selected targets separately from type-directive receipts. Source lookup queries retain observed positive and negative candidates; projection probes validate staged bindings without retaining the generated directory's pre-materialization state as immutable source evidence. [Library regressions](../../packages/limina/src/__tests__/library-projection.spec.ts) cover real Checker output, default-library checking, configuration/directive/default entries, output targets, cross-process restoration, candidate changes and modified manifest refusal.

`TypeInputProjectionReceipt` proves only `config-type-directives` entry preservation, not the complete type environment or all request relationships. Existing `outputs.target` selection and defaults remain valid. Different default libraries alone are not an error. At the governance layer, source type leaves may not contain handwritten `references`; the [config reader](../../packages/limina/src/core/build-graph/generated/config-reader-basics.ts) rejects that shape. Managed-output lookup may explain an explicitly managed output, but does not turn declaration consumption into a source relation.
