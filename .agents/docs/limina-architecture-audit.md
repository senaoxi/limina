## Scope and method

The subject was the **dirty working tree** at the start of this task. HEAD `561683d2f11985eea85d0921ed2ed1a2768f48da` identifies only the baseline origin, not the staged semantic repairs. The baseline included the user's staged `.agents/docs/limina.md`, EN/ZH dependency graph articles, production semantic/build-graph/import-analysis changes and regression tests, plus untracked `a.ts` and `b.ts`.

Status/index/content fingerprints were recorded first. Call chains were reconstructed from CLI/config → pipeline/preflight → workspace/ownership → semantic facts → graph/validation → mutation/reporting, then challenged with tests, installed compiler oracles, and external reproductions before comparing the old PCR paragraph by paragraph. Memory supplied only working boundaries and retrieval hints, not technical facts or product direction. No production behavior changed, no tests were added or weakened, and nothing was staged or committed.

**Source-established**: Phases, fields, guards, and call boundaries in this record set come from direct source inspection. **Test-backed**: Existing regressions actually executed below. **Empirically verified**: The specific conditions listed in the external reproductions. **Derived**: Cache/API integration risks. **NOT VERIFIED**: The complete optional checker version matrix, physical Windows execution, remote CI, arbitrary concurrent filesystem races, and integration/build/release checks that were not run.
