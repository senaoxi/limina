## Limina boundary

Repository security/reporting and external workflow boundaries are owned by [infrastructure](./infrastructure.md). Both products publish generated third-party license notices in `LICENSE.md`. Bundled dependency metadata is validated during the build; no separate JSON inventory is generated or published. These license and repository-report boundaries are separate from Limina's governed artifact namespace.

The private root `@limina/monorepo` orchestrates commands and shared tooling. Within this monorepo, `packages/limina` owns the public core package, `limina`; its `src`, `bin`, `schemas`, `fixtures` and `integration` retain their internal organization. The second public package, `limina-migrate`, lives in `packages/migrate`. Only their generated `dist` directories are publication targets. The migration package uses `limina` only as a workspace development dependency and embeds the required current-source core implementation at build time. Both products still share one release version; published migrate has no Limina dependency, peer or optional dependency. Its own runtime dependencies and capability peers are explicit. The core has no runtime dependency on the migration package. Workspace packages consume `limina/internal/*` source modules. The `flow`, `core`, `utils` and `check-reporting` directories use wildcard mappings; other entries are explicitly mapped. All targets point directly to current `.ts` source files. The single-file `limina/internal/flow` entry maps separately to `src/flow.ts`. These same-release entries are workspace-only; the core publication hook removes `./internal` and every `./internal/` mapping while retaining normal workers, public API, types and schema. Migrate resolves the source modules through this export map and embeds them without a migration-specific aggregate entry. The CLI-only migration package runs publint and runtime boundary checks; its installed CLI is covered by tarball smoke tests. The core retains ATTW for its TypeScript API. Field selection and delivery validation follow [dependency placement and bundling](./dependency-placement.md).

The other private workspaces are `docs`, `smoke`, `packages/build-tools`, `packages/gates` and `packages/evals`. The private `@limina/gates` owns repository license, commit, privacy, release and ESLint checks; root scripts and configurations delegate to its explicit entries. See [repository gates](./gates.md). Fixture repositories retain independent workspace manifests and lockfiles and are outside the main workspace. Gates bootstrap through TypeScript before build tools, without invoking Limina. Rolldown then builds the product before governance and consumer checks. Toolchain and dependency versions are recorded in [technology-stack](./technology-stack.md).

Root release scripts, the product and build-tools consume registry Logaria through the dev catalog (`^0.0.4`), locked to 0.0.4. No sibling Logaria build is required. The package generator resolves the catalog through pnpm and rejects unsupported local protocols.

The independent migration package preserves the existing migration transaction and governance semantics. The old `limina migration` command forwards to a local matching package or downloads that exact version through npm. Both packages share one version, release group and `limina/v<version>` tag. See [migration status](./migration.md) for evidence and the independence gate, and [Limina architecture](./limina.md) for product invariants.

The Vercel deployment CLI is a development dependency of the existing private `docs` workspace, resolved through the dev catalog and frozen lockfile. It does not join the two-package publication group; see the [infrastructure owner](./infrastructure.md).

## Implementation cohesion and boundaries

Organize implementation around a capability and its state lifetime. Types, constants and helpers used only by that capability can live beside its implementation; a separate file needs a readable responsibility, a stable interface, an adapter/process boundary or genuine reuse. File length and caller count are review signals, not independent reasons to split or merge. Direct package-internal imports are appropriate when a barrel adds no boundary. The [ESLint policy](./gates.md#eslint-structure-policy) leaves these decisions to responsibility review.

| Area                     | Cohesive implementation and retained boundary                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Core analysis            | Build-script parsing, workspace export expansion, source-config collection, coloring, generated config readers, Knip preparation, TypeEvidence orchestration, Native closure projection and the tagged cache codec own their local helpers. Source-config discovery and Coverage remain independent from successful collection. Semantic authority, execution ownership, source ownership, coverage, compilation obligations and cache restoration qualifications remain separate concepts and owners. Framework/compiler adapters and observed-input readers retain their boundaries. |
| Runtime and presentation | CLI option parsing, execution setup/run, scheduler readiness, flow-task completion, checker-host pending requests, dependency-plan construction, config-observation diagnostics and local checker resolution stay with their owners. Scheduler settlement, generation control, managed mutation, output publication and rendering state have different lifetimes. Checker host, renderer and migration-verifier process entries retain source/bundle resolution and resource ownership.                                                                                                |
| Checks and reporting     | Source and graph phase orchestration, dependency graph collection/edges/model, built-in rule predicates, the ATTW adapter, one package-entry run and one check recorder colocate their local operations. Detector domains, Knip/process adapters, proof dimensions, archive cleanup and atomic report publication retain independent responsibilities. A dependency graph document is an observation, not an execution plan.                                                                                                                                                           |
| Migration                | Planning, membership rewriting, JSONC/config edits and per-invocation group execution keep local state and helpers together. The transaction entry directly owns prepared-plan execution and write-policy dispatch. Declared-reference provenance, semantic comparison, output adoption, prepare/apply/rollback, fresh-process verification and audit publication remain distinct stages and authorities.                                                                                                                                                                              |
| Repository tooling       | Gates and build-tools retain explicit package entries; root scripts remain command/CI adapters. Documentation capture, terminal interpretation, playback and visual components keep their own responsibilities. Smoke cases remain installed-consumer boundaries.                                                                                                                                                                                                                                                                                                                      |

The package imports and workspace-only exports above remain the cross-package access contract. Colocation does not widen public exports, extend cache lifetime, move instance state to module scope or change initialization, error, Promise or disposal semantics. The [architecture workflow](./architecture-workflow.md) owns that review; structural acceptance must also follow the [development workflow](./development-workflow.md#validation-and-handoff).

## Distributable agent skill

[`skills/limina`](../../skills/limina/SKILL.md) owns the installable consumer skill. It is separate from `.agents/skills`, which contains repository maintenance procedures. The skill was adapted from [docs-islands at `1e79a5859ec667e86ceea83fa28c04b9f6bf9ed8`](https://github.com/senaoxi/docs-islands/tree/1e79a5859ec667e86ceea83fa28c04b9f6bf9ed8/skills/limina); its standalone license preserves the upstream MIT notice. This is a source migration, not a claim of remote installation or publication.

The entrypoint keeps task selection and essential boundaries; the five references cover configuration, CLI workflows, ownership, package checks, and diagnosis. Examples follow the accompanying source, while operation in another project must use that project's installed version, help, public declarations, schema, and matching source. The skill does not require a Limina checkout, impose pnpm on consumers, expose internal imports as public API, or authorize upgrades and publishing.

Output-check guidance distinguishes temporary packing and check-state writes, dependency installation, registry access and publication. It preserves the task's actual permissions and structured-report contract, separates unexecuted checks from failures and incomplete coverage, and does not infer artifact findings from a registry-authority error. These are general operating rules, without evaluation task IDs, expected report values or grading answers.

When commands, config, checker support, root discovery, caching, or package behavior change, update the relevant skill reference alongside its source owner. Keep it a task guide rather than another exhaustive schema or issue-code catalog. [Init's install command](../../packages/limina/src/commands/init/shared.ts) and both [English](../../docs/en/cli.md) and [Chinese](../../docs/zh/cli.md) CLI guides point to `senaoxi/limina --skill limina`. Existing [init tests](../../packages/limina/src/__tests__/init.spec.ts) cover the accepted installation command and the skipped-install message; prompt refusal and install failure remain separate cases. Skill migration changes this installation destination, not governance identity, relations, or cache lifetimes.

## Independent Skill evaluations

The private [`packages/evals`](../../packages/evals/README.md) workspace owns the Skill experiment controller and adapters, separately from product runtime dependencies and consumer smoke tests. It implements local execution, the 26-task calibration and the preregistered comparison workflow; validated controller records establish experiment completion and results. Repository checks must not start model evaluations.

The execution boundary uses pinned local Codex with ChatGPT authentication and its native sandbox, plus a separate local Docker verifier. Authentication stays in its original host storage; Agent tools receive no credential file, host management socket or control-plane access. The controller validates TaskSpec permissions and dependency changes before rebuilding scoring inputs. F0, prepared S0 and final S1 are distinct; incomplete evidence cannot yield a pass. Graders, sealed acceptance data and result storage remain outside the Skill revision environment. Global budget and usage records cover diagnostics, failures and retries without replacing missing measurements with invented values. The package README records current implementation limits; passing a local probe does not establish complete experiment acceptance.

Each native client uses a fresh controller-owned `CODEX_HOME`, with only a delegate to the canonical host authentication file. Host global instructions, configuration, skills and plugins are not copied; the credential delegate is removed after the client processes finish. [Native prompt inspection](../../packages/evals/src/runner/local-codex.ts) checks the assembled input without inference before budget reservation and does not inherit the attempt trace writer. New [trace captures](../../packages/evals/src/runner/native-trace.ts) also reject injected `AGENTS.md` instruction messages; legacy trace reads retain their original contract. The isolated-home lifecycle and trace negative controls have their nearest guards in the Evals tests.

Task-volume parents must be outside host Git repositories and package-manifest ancestry. A native release check can otherwise inspect an unrelated ancestor manifest before reaching the supplied output, while Docker observes only its isolated root. Choose a clean canonical temporary parent rather than granting host reads. Task prompts must explicitly authorize any temporary packing and check-state writes and declare structured-report types and path bases. Clarifying a task changes its Bank content identity; it does not justify weakening its product assertions or rewriting older calibrations and results.

Token completeness does not establish monetary settlement. The [budget ledger](../../packages/evals/src/core/budget.ts) interprets historical token-derived inclusion/zero labels as financially unknown, preserving the original journal. Independent monetary evidence can be appended without changing complete token measurements. Reports distinguish observed actual amounts, missing monetary evidence and conditional dispatch-policy bounds; included-only eligibility is not a dollar receipt. Financial reporting has its own source identity and applies uniformly across conditions, while resuming an experiment still requires its frozen execution and grading inputs. Candidate admission uses its independent included-only reservation and complete usage and trace, without requiring a monetary inclusion label. Native quota refreshes retain the separate provenance and age of reload-setting observations.

[Estimated API-equivalent cost](../../packages/evals/src/core/estimated-cost.ts) is a separate derived measurement. Its controller reads only explicitly selected runs and integrity-checked native captures, prices each request with a frozen public rate snapshot, treats cache reads as a subset of input and leaves missing or unsupported usage unpriced. Reporting records calculation, pricing and input identities; it preserves failed attempts and replacements without rewriting execution journals, grades or the actual-spend ledger. This is not subscription billing or credits deducted. The [evaluation README](../../packages/evals/README.md#estimated-api-equivalent-cost) owns commands and qualified pricing coverage.

Trace closure and token coverage are independent. A recorded `inference_failed` event is a terminal event, while its unreported token usage remains unknown. Missing terminals or referenced payloads still invalidate trace completeness; known Agent errors and incomplete final state cannot become passes. Partial reported counters are observed sums, not complete totals. After an attempt finalizes, only a fresh included-only zero-paid admission can fund further work with partial usage; paid dispatch remains blocked. Runner changes use a new campaign identity and complete registered batches, preserving earlier records and the single global budget.

Capture scope belongs to TaskSpec and participates in execution and grading identity. Runtime-cache exclusions cannot conceal fixture inputs, authorized project edits, required artifacts or Skill state; cache-behavior tasks must retain their relevant cache state. The grading budget is one monotonic phase deadline shared by reconstruction, container startup and commands, not a fresh timeout for each command. A killed Docker client remains a timeout even if it reports exit zero. See the [capture policy](../../packages/evals/src/core/capture-policy.ts) and [grading deadline](../../packages/evals/src/core/deadline.ts).

Task calibration must prove that a command exercised its intended target. The [entry-coverage](../../packages/evals/src/graders/C02.ts) and [excluded-closure](../../packages/evals/src/graders/R03.ts) Graders use real checker builds and source-specific diagnostics for TypeScript; framework-only typecheck may instead succeed as disabled. They read a fresh generated manifest after building and control automatic entry discovery so it cannot mask a missing explicit solution reference. Reference order and directory aliases are semantic equivalents, not grading failures.

Task runtimes may have distinct frozen dependency closures; installing framework peers for one task must not erase another task's missing-peer condition. The Vue checker calibration requires dependencies at project-local paths: the pinned product fails to resolve generated helper declarations with an external node_modules symlink even when direct vue-tsc succeeds. [DockerVerifier](../../packages/evals/src/runner/docker-verifier.ts) can populate a fresh anonymous dependency volume from the fixed image and mount it read-only at the project path. Preflight compares its bytes with the admitted bundle and tests denied writes and replacement; disposal removes the anonymous volume. The native Agent profile also makes project node_modules read-only. Writable dependency copies are diagnostic controls, not trusted scoring inputs.

Agent preparation copies a TaskSpec-authorized frozen dependency tree and creates only declared relative workspace links inside excluded dependency directories. It checks the complete tree before copying and again afterward; root and nested dependency paths are read-only under the native profile. The full Skill is installed before S0 and reconstructed from frozen bytes for grading. Post-run dependency integrity remains separate from project diff evidence; unknown integrity must prevent a pass. The APFS project occupies a subdirectory of its private volume, so operating-system volume metadata never requires an Agent-path capture exclusion. See [task workspace preparation](../../packages/evals/src/runner/task-workspace.ts).

Verifier memory limits are frozen in toolchain identity and must match across conditions for each task. The adapter admits only 1024 MiB (default) or 2048 MiB. Framework runtime archives may exceed project snapshot capacity, so runtime-bundle preflight has a separate 512 MiB byte limit; this does not expand Agent project capture exclusions or weaken completeness checks. Resource changes invalidate calibration identities just like other toolchain changes.

The verifier must suppress pnpm's implicit installation before run/exec. Its fixed invocation flags and nested-command environment require offline operation and ignored install scripts, and disable pre-run dependency installation only for the already-admitted immutable closure. Repository-wide dependency admission remains unchanged; explicit install plans still require frozen inputs and a lockfile. Script grading must preserve shell command boundaries: normalizing a newline into an argument separator can report success for a script that actually fails. The [output workflow Grader](../../packages/evals/src/graders/W02.ts) validates a bounded single-line grammar before executing fixed tools.

Data-only configuration can still declare executable pipeline steps. TaskSpec pipeline permissions therefore constrain built-in tasks, external commands and fixed script argument prefixes before verifier admission; they reject environment and working-directory overrides. JSON field permissions also apply to statically parsed Limina configuration, so editing a pipeline does not authorize changing governance. Parsing never evaluates the submitted module. Shared validation changes invalidate prior calibration identities; retain historical evidence and recalibrate before formal dispatch.

The [static configuration reader](../../packages/evals/src/core/static-config.ts) treats parentheses and TypeScript `satisfies` constraints as transparent value wrappers, including nested literal values. Type-only imports from Limina introduce no additional runtime capability; the sole permitted value import remains `defineConfig`. The underlying literal, field and pipeline permissions still apply. Functions, getters, computed keys, spreads and arbitrary calls remain rejected. Static admission does not establish type correctness: the independent Grader must still reject real TypeScript errors. The [current I01 edition](../../packages/evals/src/tasks/v2_1/I01.ts) makes these permissions explicit and calibrates both typed equivalents and forbidden expressions; changed contracts receive a new Bank and Runner identity without rewriting earlier results.

The experiment manifest freezes all slots before dispatch and separates execution, grading and comparison identities. Resume cannot replace Agent failures with later successes or silently shorten the plan. Foundation preflight establishes local capabilities only; task admission and calibration remain separate requirements. Reports recheck stored evidence, retain missing slots and unknown states, and aggregate tasks before equal-weight domains. Sealed report aggregates are still controller data, not feedback for the same round's Skill revision.

[Formal dispatch](../../packages/evals/src/controller/formal.ts) checks the entire calibrated suite, dependency reviews, revision isolation and the single shared budget before starting a batch. [Slot execution](../../packages/evals/src/controller/slot.ts) checks S0 against an independent reconstruction before reservation. Pre-dispatch failures leave the slot unexecuted; after reservation and launch, known Agent failures survive trace or grading errors. Only validated project state enters the calibrated Docker Grader.

The Runner repeats the synchronous controller STOP check after asynchronous account, discovery and S0 preparation, before budget reservation and slot claim. Reservation, claim and process creation follow without asynchronous work. A stop raised during preparation leaves the slot `not_run` with no reservation or model call; an already-admitted attempt retains its exit and capture. Any existing stop entry, including a directory or broken symbolic link, closes dispatch; read errors fail closed. The final check defines admission, rather than the earlier start of preparation. This correction changes Runner identity and requires a new campaign with the complete registered batches; prior records remain unchanged.

[Revision input export](../../packages/evals/src/controller/revision-export.ts) revalidates the frozen product, complete Skill and all development calibrations before copying an explicit file/field allowlist. It exports development fixtures/prompts, public contract Markdown and development-only diagnostic summaries, without Grader source, reference solutions, raw traces, evidence paths or Git history. Diagnostic evidence must match the exported product and current Skill. The fresh output must be disjoint from protected storage and outside every host Git ancestor: a directory outside the product checkout can still inherit another repository's context. Export integrity is checked again before use. Native sandbox isolation and a fresh revision session remain separate runtime requirements; a Git command failing to launch is not proof that its object files are unreadable.

### Versioned model campaigns

A campaign freezes one model profile per model and one experiment per model/stage. The existing single-slot runner, independent Docker grading and global budget ledger remain authoritative. Profiles bind exact catalog model ID, reasoning effort, requested service tier, Codex/helper hashes, native instructions and execution limits; names are presentation only. Native traces check the session, each inference event and each request payload. Missing provider-side model/tier receipts remain unobserved. Strict comparisons require matching shared execution and instruction contracts; native-profile comparisons retain their declared differences.

Session model, provider and reasoning checks use the frozen Model Profile independently of the session's sandbox permission object. Permission metadata cannot supply model defaults. The native-trace regression covers a nondefault model/effort and rejects contradictory session identities or expanded sandbox permissions. A collector correction changes Runner identity; historical attempts and their original judgments remain intact.

The V1 readers and immutable public snapshots remain available. V2 and V2.1 task-bank identities are separate from TaskSpec schema version; both require the campaign/profile route, and unknown revisions cannot fall back. V2 development definitions reuse protected V1 semantics with revised prompts and selected composition changes; sealed definitions and calibration/review packets remain private. N01 additionally compiles an independent public-API consumer. Grader calibration does not establish task calibration or model discrimination. Formal V2 dispatch requires the independent task-review receipt, complete suite calibration, per-profile preflight and smoke, and the single shared budget. V2 smoke requires all three conditions to pass and binds completion to journal prefixes; failed profiles remain unadmitted. Pilot is a separate 18-slot/model development diagnostic, never formal evidence.

Bank editions retain the complete 26-task inventory and 17/9 split. A revised prompt, fixture, permission or Grader freezes a new bank ID; historical definitions, receipts and failed independent submissions remain archived. Independent reviewers receive only task inputs and prepared tool contracts in fresh contexts, then freeze submissions before private grading. Counterfactual environments bind their own runtime and working-directory identities; they establish task calibration, not extra formal scenarios or model discrimination.

Initialization diagnosis separates the requested invocation directory from the directory returned by successful native root resolution. A blocked resolution does not promote the nearest manifest directory into a resolved governance root. The [versioned task](../../packages/evals/src/tasks/v2_1/I03.ts) declares these report meanings and permits diagnosis delivery only; generated initialization state is captured so unauthorized writes remain visible. Its [Grader](../../packages/evals/src/graders/v2_1/I03.ts) checks the report fields separately and independently observes product rejection and preservation of project state. Product probes are not evidence that the Agent performed those operations. Historical task editions and judgments retain their original contracts.

The prepared pnpm PATH entry uses a read-only, identity-bound script with fixed no-install arguments for nested calls. Explicit install commands fail before invoking the native binary; sandbox network and dependency protection remain independent. Shared source changes require fresh calibration/calculation identities. Strict historical private replay uses the archived source closure, while existing public JSON remains unchanged.

Skill installation, native discoverability, observed discovery, complete-content reads and following guidance are distinct evidence. Absent observations remain unknown. Versioned attribution is append-only and cannot change assigned conditions, outcomes or scores. V2 determinable slots require verified model/configuration evidence; raw known Agent failures remain recorded when a slot is unknown. Reports retain unresolved assigned slots and give determinable rates, coverage and bounds; regressions and lifts use same-model pairs and equal task/domain weights. Cross-model contrasts use the common frozen cells and only appear for complete strictly comparable data.

The public matrix selects the latest development and sealed report for each campaign under the exact calibrated Bank Identity, then combines those stages only within the same campaign and Model Profile. Both task inventories must have executed; unstarted slots, unadmitted models, smoke, pilot and confirmation runs do not enter the combined view. Fully executed unresolved attempts retain their original outcomes and report completion flags, with determinable coverage displayed beside the rate. A newer unfinished report never falls back to an older report. An explicitly bound current-task summary also admits the companion stage of its exact source campaign and Bank; unrelated history remains excluded. The combined view preserves stage and task provenance, does not select a best campaign or calculate cross-campaign model effects, and retains immutable historical snapshots and compatibility readers.

[RunStore grading reviews](../../packages/evals/src/core/run-store.ts) append a hash-linked adjudication for a finished `grader_error` only. The frozen task, setup and grading toolchain, complete submitted snapshots, model evidence, original record and original assertion artifact must remain bound; the offline review supplies the complete original assertion set within the frozen deadline. It can establish either a pass or an assertion failure, never replace a known Agent failure or create another execution. Run ID, usage and physical timing stay unchanged; review timing and provenance are separate. Original journal bytes and assertions remain intact, and pinned historical prefixes still read the original unknown. New reports bind the appended journal and receive new report identities.

Docs owns the typed cohort-view tests. Root tooling runs those files through its existing TypeScript test runner, keeping source imports inside Docs and retaining typecheck proof for the tests.

Campaign publication binds the exact campaign, manifests, attempt-journal and attribution prefixes, a read-only ledger snapshot, calculation sources and report bytes. Later appends cannot change an existing report, and its ledger copy has no dispatch authority. The root exporter reads package-owned public JSON over a read-only CLI boundary; the page uses a local public-data view contract. The public projection emits explicit fields; raw evidence, prompts, graders, references, private paths and monetary guesses stay private. Frozen stage schedules balance admitted participants; common final decisions explicitly retain excluded roster members. Missing report data is distinct from evidence-backed non-admission. Snapshot filenames include report identity, so later reports for the same campaign/stage coexist with earlier snapshots. The dashboard loads campaigns whose full Bank Identity matches the current calibration summary, plus the exact source campaign and companion stage of an explicitly bound current-task summary. That source must still be the latest report for its own campaign/stage; a missing or superseded source is rejected. Historical snapshots and compatibility tests remain archived. No model scores are supplied by calibration or source changes. Live model, tool/sandbox and discrimination acceptance remains an operator action; ordinary CI runs offline tests only. See the [evaluation workspace](../../packages/evals/README.md).

### Public evaluation results

The [English](../../docs/en/evals.md) and [Chinese](../../docs/zh/evals.md) result pages share an asynchronously loaded [dashboard](../../docs/.vitepress/theme/EvalsDashboard.vue) and [latest-bank summary](../../docs/.vitepress/theme/evals-latest-bank.json). Existing Vue and native tables/disclosures cover this bounded presentation without another chart runtime. The dashboard inherits the site's light/dark palette, identifies the frozen bank revision and presents one model matrix of current fully executed development and sealed results. Historical bank selectors and result links are absent from this page; their underlying snapshots remain intact.

[Calibration publication](../../scripts/docs/export-evals-calibration.ts) verifies an explicitly pinned private evidence index, the bank identity, each task's calibration and independent frozen-submission grading, and the public-input equivalence receipt. It publishes only controlled statuses, counts and source/calculation identities, writes an immutable snapshot, and atomically replaces the latest pointer. Prompts, assertion names, solutions, raw traces, free-form review text and evidence paths are excluded. Calibration matches include correctly rejected repairs and unauthorized changes; they are not Agent success rates.

Model results load lazily after the index matches the latest bank or the explicitly bound current-summary source family; each loaded bank, campaign, report and stage must match its index entry. Without both fully executed inventories for a model, the combined page produces an explicit empty state after loading, with no historical fallback, endless loading or invented rows. Measured campaigns retain paired condition comparisons, regressions, coverage, unresolved samples and minimal activation/attribution summaries. Calibration alone cannot establish model discrimination, stability or Skill lift.

Historical cost exports contain observed API-equivalent sums, including failed and replacement executions, with incomplete totals marked. Publication binds the private cost report hash and checks the exact attempt set before exporting an aggregate allowlist; request identities and trace content remain private. Estimates never populate actual settlement fields.

Frozen Standard API pricing supports exact Terra and Sol model IDs. Per-request cache and long-context rules apply to captured tokens; incomplete usage stays outside complete-attempt means and retains its observed subtotal. Offline repricing first reproduces an already-measured report with its original reviewed price snapshot, then creates a new calculation/report identity at current frozen rates. Unknown price identities are rejected. Repricing preserves execution identities, grades, raw traces, ledger entries and earlier public snapshots; it does not dispatch models or alter actual settlement. See the [cost estimator](../../packages/evals/src/core/estimated-cost.ts) and [reanalysis boundary](../../packages/evals/src/controller/campaign-report.ts).

Current Campaign reports attach [measurements](../../packages/evals/src/core/campaign-measurements.ts) to exact frozen execution sets. Input tokens, duration and API-equivalent cost average observations within each task/condition, then give available cells equal weight; model and task rows combine Base and Skill, with controls separate. Input tokens include the cached subset once. Only complete recorded usage contributes a token mean; partial input totals remain observed subtotals with execution coverage. Version 2 measurements add task aggregates and input tokens; version 1 replays without invented fields before offline reanalysis writes a new identity. Failed, unknown and replacement executions remain included. Agent duration and end-to-end time are separate. Means retain execution coverage and measured/assigned cell counts; incomplete estimates retain observed subtotals with unknown complete totals. The dashboard shows Agent/version, average duration, estimated API-equivalent cost and coverage. Its main-table success rate is verified passed attempts divided by all physical executions, with nonzero unresolved counts shown beside each condition’s determinable/execution coverage instead of a separate Unknown column. Task/domain macros remain in the retained reports and combined view under distinct fields; monetary estimates never become actual bills, and unadmitted models retain N/A formal measurements in archived reports while remaining outside the complete-results view.

[Task-result publication](../../scripts/docs/export-evals-task.ts) reuses the existing read-only Campaign publication process. The source index binds the original journal, model, bank, fixture, grading and execution identities. An explicit task selector binds I03 to development and P03 to sealed; the legacy P03 projection remains readable. I03 pointers separate nonlegacy models by canonical model ID, while the original Terra pointer remains compatible; publishing Sol cannot replace Terra sources. A one-task, one-condition result requires all three planned independent attempts to be determinable, with no replacement or hidden extra execution; complete failures remain publishable. Unexecuted parent-batch slots never become task executions or a completed formal batch. The explicit public projection retains measurements and unknown actual charges, writes an immutable snapshot and updates a task-specific pointer. Task results retain their own Bank Identity and sample scope. They supply the explicitly selected current-result summary without rewriting a historical full-bank score or supplying an unmeasured Base arm. Historical journals, unknowns, snapshots and compatibility tests remain intact.

[Current-result publication](../../scripts/docs/export-evals-summary.ts) binds the byte hashes of a complete campaign snapshot and a complete task snapshot, then selects that task condition once. A changed grading or execution contract requires an explicit revision binding the old and new Bank, fixture, grading and execution identities; it cannot waive an unrelated mismatch. The page admits one selection per campaign/model/stage, so development I03 and sealed P03 update the same model row without replacing each other. It recomputes counts, task/domain macro rates, descriptive condition differences, duration, cost and coverage; controls remain separate and unknown costs remain unknown. The public summary has its own calculation/content identity and retains both source banks and reports, selected/source execution counts, and immutable historical files. The page folds selected tasks into one model row and its task table; it never presents a second task score table. Different-source conditions do not acquire a same-experiment pair, and their descriptive difference is not a new causal Skill estimate. Retained summary artifacts bind each row to its exact source references; the page does not add download panels.

The page opens with one model table combining development and sealed results, without a stage selector. The [combined view](../../docs/.vitepress/theme/evals-combined.ts) computes main and negative-control success rates as passed/all executions; each displayed percentage derives from the adjacent numerator and denominator. Differences use the same execution rates. Unknown results stay in the execution denominator, have their own counts and retain determinable/execution coverage; this does not classify them as known Agent failures. Infrastructure replacement executions remain in the denominator and unresolved count. Original task/domain macros and their differences remain separately named in the combined data and immutable source reports. Measurement means retain equal task/condition cell weights. Controls have independent counts and a static table and never enter main rates or measurements. Expanding a model shows 24 main tasks and two controls with original split labels, input tokens, Agent duration, API-equivalent cost, coverage and individual attempt markers. Task rows have no nested disclosures. Each stage report and explicitly selected task source retains its original identity; this descriptive union creates no new experiment or cross-source pair. A zero-execution rate remains N/A; evidenced zero successes remain 0%. Markers retain physical attempts, including replacements, with symbols and accessible status. Methodology, source, calibration and historical evidence artifacts stay archived independently of the page. The visual reference is the [Next.js Evals table](https://nextjs.org/evals), without adopting pass@k or dropping unresolved evidence.

[Offline report reanalysis](../../packages/evals/src/controller/campaign-report.ts) uses a pinned historical source index and its ledger snapshot, without opening a writer or reading the live ledger.
