Keep this output check outside the managed source solution to avoid requiring distribution files during source discovery. Run `pnpm --filter limina run build:types:check` to recheck existing output; root builds and their CI callers execute it after regenerating output. Package boundary checks and packed-consumer tests retain ownership of dependency completeness and installed export resolution; this check does not replace them.

## Astro test baseline and compatibility floor

The test catalog's `astro` entry selects the reviewed Astro 7 baseline; `astro-v7-min` remains the fixed 7.0.0 compatibility floor. Both are development dependencies of Limina. Their published package versions and artifacts are unchanged by using the canonical baseline name. Production discovery still resolves `astro` from the owning consumer leaf; test naming does not change semantic admission or permit workspace-root fallback.

The shared [Astro test toolchain reader](../../packages/gates/src/test-support/astro-toolchain.mjs) reads exact versions from the caller-owned frozen installation selected by the catalogs and lockfile. Installed unit fixtures and [packed-consumer smoke](../../smoke/helpers.ts) use the private `@limina/gates/test-support/astro-toolchain` export for baseline dependency versions; smoke also pins the check-owned Language Server, compiler and Volar instances from their actual owners. Astro smoke uses the same default TypeScript baseline in its root and leaf, while explicit lower-version cases retain their overrides. Consumer creation inherits the invoking pnpm executable, including pnpm 12's native entry, before the temporary manifest exists.

The reader is directly executable ESM with bootstrap-generated declarations. Callers supply their fixture owner's `NodeRequire`; gates do not import a product or resolve fixture dependencies from the gates package. Keep the explicit workspace export: cross-package relative imports violate source ownership, sharing TypeScript implementation source would join smoke's tsgo and the repository's vue-tsc declaration components, and a same-stem authored declaration would hide the JavaScript root from configuration discovery. Do not repeat the baseline patch version or semantic tuple in fixture installation configuration. Synthetic admission tuples and explicit minimum-check/TypeScript-5 smoke inputs remain independent boundary cases, rather than following the baseline automatically.

[Renovate](../../.github/renovate.json) matches checker dependency names, including aliases, through `matchDepNames`. It disables updates for `astro-v7-min` and limits the canonical `astro` baseline to reviewed, exact `>=7.0.0 <8.0.0` updates in the checker compatibility group. Dashboard approval, no automerge, release-age and trust requirements remain active. A baseline update must regenerate the lockfile, install frozen dependencies and exercise both Astro versions plus packed-consumer smoke against the admitted complete checker tuples. A new Astro major requires a separate compatibility change. Raise the minimum fixture only with an explicit change to the supported minimum, its independent floor assertion and the relevant admission contract; do not raise it through routine dependency maintenance.

These are repository test-maintenance policies, not additional product support guarantees. The [semantic owner](./semantics.md#locked-resolution-and-framework-preparation) defines toolchain authority and the supported tuple boundary. Local verification does not establish Windows/Linux or remote CI acceptance.

## ESLint 10 migration

Repository automation, security reports, CI reuse and gated external workflows are owned by [infrastructure](./infrastructure.md). Root tooling adds only the already cataloged YAML parser; dependency versions and the task runner remain unchanged.

The lint catalog now resolves ESLint 10.11.0, typescript-eslint 8.71.0, Unicorn 76.0.0, Node plugin 18.4.0, pnpm plugin 1.9.1, HTML plugin/parser 0.66.1, Prettier plugin 5.5.6, flat-gitignore 2.4.0, JSONC parser 3.3.0 and YAML parser 2.1.0. Existing Prettier config 10.1.8 and globals 17.12.0 remain current. Regexp now resolves to 3.3.1; its parser requires Node `^22.22.2 || >=24.15.0`, compatible with the current Node range. The former baseline blocked that upgrade and previously required `~3.1.1`; that historical restriction is no longer a current version constraint. The obsolete HTML parser wildcard hook and its now-unreachable minimatch 3 patch/overrides were removed.

The complete new Unicorn recommended preset is enabled for JavaScript and TypeScript, followed by the repository's existing rule overrides. It is not applied to YAML/JSON/HTML parser nodes. Root composition imports explicit root file settings rather than selecting every `files` entry from the composed preset, so it cannot accidentally reapply recommended rules after shared overrides. Executable controls in the [config suite](../../packages/gates/src/eslint/__tests__/general.spec.ts) cover YAML comment preservation, JavaScript fixes and override ordering. Root commands continue to pass an explicit config path despite ESLint 10's file-based lookup.

The `@types/node` catalog and override remain at 22.18.0, independently of the runtime minimum; the ES2023 emit target and existing type libraries remain unchanged. This baseline change does not add runtime APIs. The repository-wide rule remediation preserves cache lifetime, Promise identity, fixture boundaries and code-unit string ordering; mutable module state remains owned by the same module. Error wrapping and literal package-import substitution are described by the [system model](./system-model.md#failure-semantics-and-projection-boundaries).

The archived ESLint 10 report records its local baseline, three independent adversarial rounds, check results and uncovered conditions; [migration history](./migration.md#historical-evidence) explains retrieval from Git. This evidence does not waive independent CI, publication or deployment gates.
