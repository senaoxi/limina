npm publication remains gated. The public documentation route recorded by [Infrastructure](./infrastructure.md#external-gates-and-collaboration) does not enable the repository's separately gated deployment workflow. Before release: pass clean independent installation and the full remote CI matrix; select an unpublished version; verify npm trusted publisher, workflow and `Release` environment; freeze old publication authority before enabling new publication. Historical tags must not publish automatically. Release scripts target only the approved `packages/limina/dist` and `packages/migrate/dist` pair with matching names, versions and the shared `limina/v<version>` tag. The migration publication manifest must contain no Limina dependency in its runtime, peer, optional or development fields, and no private workspace or unresolved local protocol. Its non-public `migration-build.json` must match both products’ source/dist versions and the release version; CLI, fresh verifier and renderer resources must exist. Release order remains explicitly core then migrate even without a runtime edge. All workspace-only internal source module mappings are removed from the core publication exports. This is a breaking package surface change: select an unpublished breaking version for both products before release; this local implementation does not bump the source versions or authorize publication. Publication uploads under a candidate npm tag, verifies both artifact integrities, and only then promotes the channel. A retry accepts an existing version only when its integrity matches; it never overwrites a published version. Historical changelog entries retain their original links; commit-map-aware new entries distinguish old and new repository history.

The current public route, fixed base, Vercel gateway and deployment configuration are owned by [Infrastructure](./infrastructure.md#external-gates-and-collaboration). Project association and deployment authority remain subject to their independent gates. Migration of old consumers remains a separate gated action: migrate old consumers to an approved registry version, honor release age/trust, remove old source and Nx/release ownership, validate the old repository, then redirect any remaining old bilingual documentation routes including assets, query parameters and anchors.

Before publication, rollback means stopping the cutover and retaining the old repository. After publication, roll back consumer versions, documentation routes and workflows separately; do not overwrite published versions, unpublish or force-push history.
