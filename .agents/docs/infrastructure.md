# Repository infrastructure

This record owns standalone repository dependency automation, collaboration, security, CI reports and external workflow integration. Sources establish behavior; local results do not establish remote activation or platform acceptance.

## Dependencies and security

[Renovate](../../.github/renovate.json) proposes reviewed catalog/lockfile updates without automerge. Peer/engine contracts and independent fixtures are excluded. Checker families, package-manager changes and majors require dashboard approval; Vite 5 stays on its existing line. No second update bot or old postinstall bootstrap is introduced.

The private [pnpm ESLint adapter](../../packages/eslint-config/src/plugins/pnpm-plugin/index.ts) counts catalog references in parent/version-qualified overrides. Upstream eslint-plugin-pnpm 1.9.1 incorrectly treats the whole selector as the package name; the adapter suppresses only those false unused-item reports and preserves genuinely unused reports. The root duplicate-catalog rule adds `path-to-regexp` alongside the existing Vite allowance because the deployment graph needs both major 6 and 8 APIs. This is a named lint allowance, not an audit, trust or dependency-admission exception. The ESLint owner-boundary regression exercises real temporary workspaces, including a scoped version-qualified selector, and demonstrates the upstream failure alongside the adapted result.

[Dependency review](../../.github/workflows/dependency-review.yml) covers runtime/development/unknown scopes at high severity. Its list mirrors the pre-existing [bundled-license policy](../../packages/build-tools/src/license-policy.ts), guarded by [infrastructure:check](../../scripts/infrastructure/check.ts). No old license exception is imported. The action does not exhaustively reject unknown license metadata; the bundle gate separately rejects missing/conflicting/prohibited evidence. Non-bundled dependencies still require admission review.

[Security CI](../../.github/workflows/security.yml) runs all-class audit and reachable-history secret scan on PR/main/weekly/manual events. Gitleaks CLI 8.30.1 is MIT and uses the official Linux archive's pinned SHA-256, avoiding the old separately licensed action. No fixture-wide or VitePress-report exemption is added. Reports are redacted; no automatic issue/PR messaging is introduced. [Audit parsing](../../scripts/infrastructure/audit.ts) accepts pnpm 11 advisory JSON and fails on process/registry/schema errors. High/critical decisions count returned details after existing exclusions, because metadata may still count excluded entries. Existing workspace GHSA/trust exceptions remain visible and require separate review; this integration adds none.

Security maintenance uses the `security-patches` catalog in the [workspace configuration](../../pnpm-workspace.yaml). It retains the existing scope of the undici and minimatch 10 brace-expansion overrides, and limits the added fast-uri and moment overrides to Ajv 8 and rollup-plugin-license respectively. The 2026-09-30 local all-class audit returned no advisory entries under the 18 unchanged GHSA exclusions. Release-age, trust and peer policies remain in force; no new audit, trust, release-age or deprecation exception was added.

[CodeQL](../../.github/workflows/codeql.yml) explicitly loads its [scope](../../.github/codeql-config.yml), analyzes JavaScript/TypeScript without a product build and includes both products/private tools/scripts, excluding generated output/fixtures/tests. Static scanning is not exhaustive runtime/filesystem proof.

## CI and artifacts

The shared build action invokes the root `format:check` script for read-only Prettier validation. The root manifest must provide that script; formatting mutation remains an explicit `format:write` operation.

[CI](../../.github/workflows/ci.yml) preserves native platform builds/tests/smoke and isolated Vue tuples. Linux quality reuses the same commit/platform's package artifacts; other environments build/check independently. Explicit build is followed by test:smoke without rebuilding. No path filter, Nx cache or cached .limina state is introduced. CI Status depends on every validation job and rejects failure/cancellation/skipped jobs.

The license plugin emits bundled-dependencies.json from actual bundler inputs, including bundled development dependencies, and rejects missing metadata while retaining the existing license list. artifacts:report packs both approved dist directories with an exact-version migration dependency, verifies packaged inventory, independently recomputes SHA-512 and records actual gzip/unpacked bytes. .reports/release contains tarballs, license reports, CycloneDX 1.6 SBOMs and group metadata. Components describe bundled code; external runtime/peer/optional ranges are properties. Consumer-selected versions and external transitive dependencies are outside this scope.

Repository reports are separate from the governed .limina namespace. Product invariants I01–I12 and guards remain unchanged; do not generalize I10/I11 to arbitrary reports/external services. Report failure stops CI/release progression.

## External gates and collaboration

[Publication](../../.github/workflows/publish-npm.yml) remains manual and restricted to senaoxi/limina, LIMINA_RELEASE_ENABLED=1 and Release. [Tag checks](../../scripts/release/check-tag-cli.ts) reject imported tags, require both source versions, exact tag checkout and origin/main ancestry. Existing paired npm integrity/retry semantics remain authoritative. [GitHub release tooling](../../scripts/release/github-release.ts) compares both registry/tarball integrities, creates a draft, uploads only current named assets and exposes it after success. Retry compares existing bytes without replacing different assets; failures retain the draft.

[Docs deployment](../../.github/workflows/deploy-docs.yml) is separately manual and gated by LIMINA_DOCS_DEPLOY_ENABLED=1 and Production. It needs a new approved tag, HTTPS DOCS_ORIGIN and independent Vercel credentials/project. The private `packages/deploy-tools` workspace consumes Apache-2.0 Vercel CLI 56.3.1 through the dev catalog and frozen lockfile. It is deployment-only. pnpm 11 deduplication adds optional `@edge-runtime/vm` and `@vercel/blob` peers to the host Vitest/Astro contexts; their package versions and the independent compatibility-fixture workspaces remain unchanged, and the full host test gates are rerun. An attempted 61.0.0 upgrade was rejected by pnpm `ERR_PNPM_TRUST_DOWNGRADE`; no exception was added. Registry, source-tag and archive license evidence agree for the selected version. Deployment also runs the dependency audit before external operations. Narrow parent-specific catalog overrides update tar, both path-to-regexp API majors, Ajv and once in the new deployment graph. They remove the newly introduced advisory entries without adding exclusions or changing the existing global peer/trust policy. The selected CLI is not deprecated; its upstream stream-to-promise transitive dependency remains deprecated and is an explicit maintenance limitation, not an allowedDeprecatedVersions exception. The docs site has a fixed `/repos/limina/` base in development and production. An origin enables sitemap generation under that base. The Senao site owns the external `/repos/limina/*` gateway to the independent Limina Vercel deployment; the Limina project itself does not duplicate that routing contract. No additional origin, old project identity, redirect or broader cutover authority is inferred. Both workflows retain [migration prerequisites](./migration.md); local integration performs no external operation.

PR titles are checked through a metadata-only workflow without PR checkout. Templates collect package/command/cwd/checker/reproduction/actual checks. English contribution/security policies and project-only editor settings are provided, without automatic fixture formatting.

Administration separately enables Renovate, supported dependency review/code scanning, private security reports, labels, protected environments and required checks. Suggested checks: CI Status, Dependency Review, Dependency Audit, Secret Scan, CodeQL, PR Title. Local files do not enable settings or establish feature availability.

## Validation ownership

Root test:tooling owns malformed audit evidence, misleading counts, missing/conflicting bundle licenses, SBOM scope and historical tags. Existing tests did not own these new boundaries; tested exports have production consumers and no test-only seam is added. Root YAML is an already cataloged dependency for real configuration validation. The deployment CLI stays in a private workspace; neither addition enters product code. Normal build/tooling/unit/integration/smoke/typecheck/check/package/lint/format/docs gates apply; security:audit stays separate from pre-existing vulnerabilities. Actual outcomes and reproduction limits are in [integration validation](../../migration/INFRASTRUCTURE.md).
