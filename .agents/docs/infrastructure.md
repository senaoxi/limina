This record owns standalone repository dependency automation, collaboration, security, CI reports and external workflow integration. Sources establish behavior; local results do not establish remote activation or platform acceptance.

## Dependencies and security

[Renovate](../../.github/renovate.json) proposes reviewed catalog/lockfile updates without automerge. Peer/engine contracts and independent fixtures are excluded. Checker families, package-manager changes and majors require dashboard approval; Vite 5 stays on its existing line. No second update bot or old postinstall bootstrap is introduced.

The private [pnpm ESLint adapter](../../packages/eslint-config/src/plugins/pnpm-plugin/index.ts) counts catalog references in parent/version-qualified overrides. Upstream eslint-plugin-pnpm 1.9.1 incorrectly treats the whole selector as the package name; the adapter suppresses only those false unused-item reports and preserves genuinely unused reports. The root duplicate-catalog rule adds `path-to-regexp` alongside the existing Vite allowance because the deployment graph needs both major 6 and 8 APIs. This is a named lint allowance, not an audit, trust or dependency-admission exception. The ESLint owner-boundary regression exercises real temporary workspaces, including a scoped version-qualified selector, and demonstrates the upstream failure alongside the adapted result.

[Dependency review](../../.github/workflows/dependency-review.yml) covers runtime/development/unknown scopes at high severity. Its allowed-license list is maintained in [configuration](../../.github/dependency-review-config.yml) alongside the [bundled-license policy](../../packages/build-tools/src/license-policy.ts); there is no separate configuration synchronization script. The action does not exhaustively reject unknown license metadata; the build plugin separately rejects missing/conflicting/prohibited bundle evidence. Non-bundled dependencies still require admission review.

[Security CI](../../.github/workflows/security.yml) integrates dependency audit, license reporting, directory SBOM generation and a reachable-history secret scan on PR/main/weekly/manual events, following the docs-islands workflow organization. Bash/jq steps directly parse pnpm advisory JSON and fail on process, registry or schema errors; high/critical decisions count returned advisory details after existing exclusions. Reports are retained as workflow artifacts, with aggregate failure/cancellation/skipped states rejected by Security Summary. Gitleaks CLI 8.30.1 retains its official Linux archive checksum and redacted reports. No automatic issue/PR messaging or new audit/trust exclusion is introduced.

Security maintenance uses the `security-patches` catalog in the [workspace configuration](../../pnpm-workspace.yaml). It retains the existing scope of the undici and minimatch 10 brace-expansion overrides, and limits the added fast-uri and moment overrides to Ajv 8 and rollup-plugin-license respectively. The 2026-09-30 local all-class audit returned no advisory entries under the 18 unchanged GHSA exclusions. Release-age, trust and peer policies remain in force; no new audit, trust, release-age or deprecation exception was added.

On 2026-10-01, registry audit returned six devalue advisories against the Astro host dependencies. The `astro@^7.0.0>devalue` override selects the [5.9.3 security patch](https://github.com/sveltejs/devalue/releases/tag/v5.9.3) from that catalog, within both installed Astro versions' declared `^5.8.1` range. Astro 7.0.0 and 7.3.2 and the independent compatibility-fixture workspaces retain their versions and boundaries. The selected patch is MIT, is not deprecated and was published on 2026-09-18. Frozen installation and the local all-class audit passed, with zero returned advisories under the same 18 exclusions; no policy exception was added.

[CodeQL](../../.github/workflows/codeql.yml) explicitly loads its [scope](../../.github/codeql-config.yml), analyzes JavaScript/TypeScript without a product build and includes both products/private tools/scripts, excluding generated output/fixtures/tests. Static scanning is not exhaustive runtime/filesystem proof.

## CI and artifacts

The shared build action invokes root `format:check` and `lint:check` scripts for read-only Prettier and ESLint validation. Both commands cover the repository; mutation remains explicit through `format:write` and `lint:fix`, which reuse the current `format` and `lint` commands.

[CI](../../.github/workflows/ci.yml) preserves native platform builds/tests/smoke and isolated Vue tuples. Linux quality reuses the same commit/platform's package artifacts; other environments build/check independently. Explicit build is followed by test:smoke without rebuilding. No path filter, Nx cache or cached .limina state is introduced. CI Status depends on every validation job and rejects failure/cancellation/skipped jobs.

The full matrix's Unit Tests step caps Vitest at two workers through `VITEST_MAX_WORKERS`, leaving capacity for CLI child processes and framework hosts. Isolated CLI fixtures physically copy runtime source while excluding `__tests__` directories; their dependency links, compiler shims and repository boundaries remain fixture-owned. Test selection, security assertions and timeouts are unchanged.

The [license plugin](../../packages/build-tools/src/license.ts) retains bundled-dependencies.json from actual bundler inputs, including bundled development dependencies, and rejects missing/conflicting/prohibited metadata. The security workflow explicitly selects limina and limina-migrate for `pnpm licenses list --prod --json`; this source-manifest dependency report does not replace the bundle license gate. After building both products, the pinned Anchore/Syft action scans the working directory and generates a CycloneDX SBOM under .reports/sbom. The scan is directory-scoped and is not a per-tarball dependency inventory or consumer-resolution guarantee. Raw audit data and Markdown reports live under .reports/security; license data and reports live under .reports/licenses. Custom archive-size, SHA-512 and per-package SBOM reporting has been removed.

Repository reports are separate from the governed .limina namespace. Product invariants I01–I12 and guards remain unchanged; do not generalize I10/I11 to arbitrary reports/external services. Audit/license/SBOM report failures fail the Security workflow. Publication and deployment independently require native dependency auditing; requiring the Security workflow before merge or release depends on repository administration.

## External gates and collaboration

[Publication](../../.github/workflows/publish-npm.yml) remains manual and restricted to senaoxi/limina, LIMINA_RELEASE_ENABLED=1 and Release. [Tag checks](../../scripts/release/check-tag-cli.ts) reject imported tags, require the complete public source package names/versions, exact tag checkout and origin/main ancestry. Existing paired npm integrity/retry semantics remain authoritative. Publication and deployment use native `pnpm audit --audit-level high` before external operations. After both npm packages are verified and promoted, the publication workflow directly creates a GitHub release linking the two packages’ shared changelog at the checked-out approved commit, resolved through Git rather than the dispatch event SHA. It accepts an existing completed release for that tag; drafts and lookup errors fail. SBOM and license reports remain workflow artifacts, with no custom tarball/report attachment pipeline. The release-owned imported tag-name guard remains effective without the deleted migration metadata; moving an imported tag does not make its name publishable.

[Docs deployment](../../.github/workflows/deploy-docs.yml) remains separately manual and gated by LIMINA_DOCS_DEPLOY_ENABLED=1 and Production. It needs a new approved tag, HTTPS DOCS_ORIGIN and independent Vercel credentials/project. The workflow executes the Vercel CLI from the existing private docs workspace while keeping the repository root as its project cwd. The existing CLI version belongs to the dev catalog and frozen lockfile, with the same scoped deployment security overrides; the removed deployment workspace stays removed. The CLI is a docs development dependency and is outside both published packages. The canonical public documentation entry reported by the maintainer on 2026-10-01 is `https://senao.me/repos/limina/`. The docs site keeps its fixed `/repos/limina/` base; an origin enables sitemap generation under that base. The Senao site owns the external gateway to the independent Limina Vercel deployment. Both workflows retain [migration prerequisites](./migration.md); local integration performs no external operation.

PR titles are checked through a metadata-only workflow without PR checkout. Templates collect package/command/cwd/checker/reproduction/actual checks. English contribution/security policies and project-only editor settings are provided, without automatic fixture formatting.

Administration separately enables Renovate, supported dependency review/code scanning, private security reports, labels, protected environments and required checks. Suggested checks: CI Status, Dependency Review, Dependency Audit, Secret Scan, CodeQL, PR Title. Local files do not enable settings or establish feature availability.
