# Run Limina’s bounded architecture checks

These maintainer tools check whether a finite protocol can reach a forbidden state. Start with the [architecture workflow](../../.agents/docs/architecture-workflow.md) to find the production owner and the [existing invariants](../../.agents/docs/invariants.md). A model consumes trusted compiler facts. It does not resolve modules, infer TypeScript diagnostics, decide framework capabilities, or authorize an execution.

From the repository root with a supported Node and Java, use an existing copy of the [locked TLC release](./toolchain.json). Set `TLA2TOOLS` to its absolute path, or leave it unset to try the versioned pstack-statechart user cache. The runner verifies the bytes on every use and executes that copy from a fresh private directory, so the release manifest cannot add a sibling CommunityModules.jar from the source directory. It never installs anything. No Skill, pnpm package or network connection is required for TLC. Implementation replays additionally require the workspace's normal installed dependencies.

```sh
RUN=$(mktemp -d)
node verification/formal/run.mjs --check-map
node verification/formal/run.mjs --suite pilot --out "$RUN/pilot"
node verification/formal/evidence/runner/replay.mjs "$RUN/runner-controls"
node verification/formal/run.mjs --suite phase1 --out "$RUN/phase1"
node --import tsx verification/formal/evidence/managed-cache/replay.mjs "$RUN/bridge"
node --import tsx verification/formal/evidence/epoch/replay.mjs "$RUN/epoch"
node verification/formal/run.mjs --suite graph-ownership --out "$RUN/relations"
```

The output path itself must **not** exist. Use `--suite admission` or `cache` for one domain, `all` for every profile, or `stable` for the small observation set. To reproduce a particular trace, e.g. `--suite admission --profile admission/mutation-old-graph.cfg --out "$RUN/stale-graph"`. The runner controls use a disposable copy with a bad JAR, changed verdict expectations, a forced deadline and an upstream source edit. Exit zero for a suite means every selected profile matched its declared verdict, including expected counterexamples. An unexpected pass, different violation, missing tool, unreviewed mapping, budget overrun or incomplete search fails the command.

| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| [CacheReopen](models/cache/CacheReopen.model.json)                       | Can cooperating writers replace newer bytes or a reader accept an unbound projection? Content, ownership, references, block existence and physical revision are separate.                                      |
| [ReferenceProjection](models/projection/ReferenceProjection.model.json)  | Does a serialized small graph cover independently required leaves, bind targets and preserve exact checker rules? No compiler or path-resolution oracle.                                                       |

ReceiptSlot, EpochValidation and AnalysisPublication are retained preflight experiment modules. Their historical source baseline is `6fe3edaa1305b7d4fcedb7e4dd4ff4f0d94efeac`; the per-model contract identifies the actual reviewed product revision. The restore and two-writer protocol deliberately lives outside the historical publication module. No model claims liveness or uses fairness. A terminal self-loop represents intentional quiescence; a no-deadlock verdict alone does not establish eventual completion. One reader, a bounded number of writers/replans, and finite graph shapes exclude other schedules.

## Read a verdict

Each profile gets its own copy of the source and CFG, an untouched `tlc.out` and a record in `run.json`. The report records tool and input hashes, current HEAD, reviewed baseline, OS/JVM/Node, constants, enabled and non-configured rules, effective arguments, exit codes, initial/generated/distinct/queued states and time. The report also identifies the runner, catalog and tool lock by hash; each selected model contract is saved alongside it. Direct TLC stops at the first violation. The runner removes **only the already witnessed invariant** in a scratch CFG and repeats until all remaining invariants and deadlock checking have an exhaustive, nonempty verdict. A queue left at the first violation is normal; it is not a completeness claim. See [the epoch trace and replay](evidence/epoch/README.md) and [the managed cache witness](evidence/managed-cache/README.md). For an independent first-violation check, use the raw command in the report with the configured JAR in a new copy of that profile directory.

- `holds`: checked for all reachable states **inside this configuration**. `breaks`: raw TLC named this rule in a counterexample. `unchecked` or `incomplete`: no usable verdict; investigate the execution or bounds. `notConfigured`: rules of this module deliberately outside this CFG (typically reachability controls).
- A mutation is a hypothetical faulty design. A cover profile intentionally negates a legal observation and must break; it is not a failed safety contract. An internal API replay does not establish CLI reachability. The independent fixture, raw diagnostic and observed effect decide an implementation claim.
- Intent is a human/product decision. The owning PCR and competing examples establish specification scope. TLC checks the bounded model. Real production entry points, compilers, independent success controls and filesystem observations check the implementation. Do not promote a result between these levels.

## Review a change

Each `*.model.json` has the scope, source and consumer mapping, variables, initial state, actions, assumptions, safety, liveness, fairness, profiles, bounds, counterexample interpretation, empirical verification and drift baseline. Declare explicit absences. Start from the actual controller/caller, document why actions are atomic, split observable async or effect boundaries, identify the trusted facts and state which independent oracle could refute the rule. Keep the invariant definition with its existing PCR owner.

1. Run `--check-map`. It checks the named anchors and hashes the full mapped source/PCR/test files, including upstream producers and downstream consumers, and the exact module/profile inputs (UTF-8, normalized LF). A path not listed is not automatically protected: after a new provider, caller, tool tuple or topology change, trace adjacent components, even if hashes match.
2. Re-read both affected ends of the contract; inspect the initial states, constants, any narrowing of actions and guard removal. Run current implementation witnesses and adversarial controls. On drift, use `--review-hashes` for candidate fingerprints. This command cannot update a stamp or yield a check verdict. Review the difference, edit the contract hashes and product baseline, then rerun the affected suite and its real witness. Baseline is the reviewed **product** commit, not a self-reference to the commit adding the model.
3. For a new counterexample retain a small sanitized trace excerpt, baseline/profile and exact command, the first diverging transition, and an implementation witness or explicit `needs-review`. Record whether the result is model only, internal API, or observed in the production entry. Check omitted guards, scheduler constraints, and unmodeled actions before assigning a bug. Keep bulk logs, states, temporary configs, JARs and dumps out of Git. Do not weaken a property or add fairness/pruning to turn a run green.

## CI observation and tool admission

The [separate workflow](../../.github/workflows/formal-verification.yml) does not participate in product CI Status. Its implementation witness job replays the real cold/warm and epoch boundaries without a JAR. It checks mappings without TLC; after tool review it runs the small suite on PRs and all profiles on manual/weekly runs. The JAR is the only TLC cache entry. The runner rehashes it on a cache hit. Jobs use one TLC worker, one configuration at a time, 1 GiB heap, a two-minute total deadline per profile (including rechecks), a per-model distinct-state acceptance ceiling, and a ten-minute model job. State budgets are checked at verdict time; timeout and heap bound work during the search. No saved verdict or TLC search state is reused.

Use the unmodified [TLC 1.7.4 distribution](https://github.com/tlaplus/tlaplus/releases/tag/v1.7.4) only for verification. A local reimplementation or generic state diagram does not implement its semantics. The upstream [tagged license](https://github.com/tlaplus/tlaplus/blob/v1.7.4/LICENSE) and the JAR's `License.txt` identify the MIT-covered tools; the [release build](https://github.com/tlaplus/tlaplus/blob/v1.7.4/tlatools/org.lamport.tlatools/customBuild.xml) also bundles third-party classes, including mailapi and SMTP 1.6.3 and the Java activation JAR named in that build. The released manifest identifies upstream revision `5a47802b5c391f59ecdd44117981f4ff8c0656ba`. The shipped `META-INF/LICENSE.txt` contains EPL-2.0 and secondary-license text. Preserve notices; distribution can entail source-availability obligations. Do not vendor the JAR, upload it as a report, or bundle it in a package. Host Java is a prerequisite, not a product dependency.

**CI acquisition is pending maintainer review** under [dependency admission](../../.agents/docs/dependency-admission.md#license-compatibility). Review the exact artifact, bundled terms and [upstream advisories](https://github.com/tlaplus/tlaplus/security/advisories) including the bundled versions for internal CI use and caching. Only after acceptance should a maintainer set the repository Actions variable `LIMINA_TLC_REVIEWED_SHA256` to the reviewed digest. A missing or different value leaves TLC unexecuted, never a passing observation. Version changes reopen the review. Do not change the product license allowlist to enable this workflow.

Promotion is a separate decision: at least ten consecutive relevant observations with all intended mutants detected, zero unchecked rules, PR-suite P95 ≤3 min, a clean Linux witness and a deliberate broken-model failure. Keep unexecuted/cancelled runs out of the successful sample. Only then select an independent required check that actually executes on every PR. Existing native platform tests still own compiler launches, filesystem semantics and other operating systems.
