# Proof Allowlist

`proof.allowlist` records exceptions for specific files that remain within the source governance boundary but intentionally have no checker or generated-graph coverage. It affects only coverage proof: it does not change checker inputs, hide type diagnostics, or authorize cross-package imports.

```ts
import { defineConfig } from 'limina';

export default defineConfig({
  proof: {
    allowlist: [
      {
        file: 'packages/core/src/generated/runtime.d.ts',
        reason: 'Generated by the runtime build; this type-check run does not consume it.',
      },
    ],
  },
});
```

## `allowlist`

- **Type:** `Array<{ file: string; reason: string }>`

Declare exceptions per file so they can be reviewed when a file's purpose or checking scope changes. If a file does not belong to this run's governance at all, adjust the [source boundary](./source-boundary.md) first instead of adding a coverage exception.

## `file`

- **Type:** `string`

`file` is relative to `config.rootDir`; external activated packages may use `../`. It must point to an existing, specific file inside the source boundary that has neither checker nor generated-graph coverage. Globs cannot widen an exception.

An entry is invalid if the file does not exist, is already outside the source boundary, or has coverage without the allowlist. Remove the exception when the file regains ordinary coverage.

## `reason`

- **Type:** non-empty `string`

Explain why the file is kept and why the current checking scope does not cover it. The reason should help maintainers decide whether the exception still applies.

## How an Exception Affects Results

If the `runtime.d.ts` above is inside `config.source` but has neither checker coverage nor generated-graph project coverage, `proof check` reports it as uncovered source. A valid allowlist entry lets coverage proof accept the exception while retaining its reason in the config.

This does not mean the file has passed type checking. If a checker entry later begins covering it, the allowlist entry becomes redundant. Remove the exception and maintain the file under ordinary coverage rules.
